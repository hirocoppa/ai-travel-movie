# AI Travel Movie

写真と動画を端末内で編集し、最大3分の旅行ダイジェストMP4を作る無料Webアプリです。Phase 1の基本編集版です。**AIによる素材選別・見どころ抽出はまだありません。BGMはCC0ライセンスの録音済み音源から毎回自動選曲します（AI音楽生成ではありません）。**

既存の `my-first-project` とは独立したプロジェクトです。有料API・アカウント・外部サーバーへの素材アップロード・アクセス解析は使用しません。

## 使い方

1. 公開されたアプリを最新のiPhone Safariで開きます。
2. 「写真・動画を選択」で複数の素材を選びます。
3. 撮影日時を確認します。日時が不明な素材は入力してください。入力した日時が古い順に並びます。入力欄の時差は端末の設定に従います。旅行先の現地時刻しか分からない場合、端末の時差に換算して入力してください。
4. 表示順を確認してチェックを入れ、「3分動画を作成」を押します。
5. 作成中は画面を開いたまま待ちます。完成後に動画を再生します。
6. 「共有して写真に保存」を押し、iPhoneの共有シートで「ビデオを保存」を選びます。見当たらない場合はMP4をダウンロード／ファイルに保存し、ファイルアプリで開いて共有 →「ビデオを保存」を選びます。

Webサイトから写真ライブラリへの直接保存はできません。写真への保存にはユーザーの操作が必要です。

## 実装済み

- 日本語・タッチ操作向けレスポンシブUI、一括選択、追加・削除、進捗、中止、再編集。
- JPEG / PNG / HEIC / MOV / MP4の読み込み可否を端末上で確認し、非対応形式・コーデックを個別に表示。
- EXIFのDateTimeOriginal（なければCreateDate）と時差情報を取得。時差不明なら自動確定せず手動確認。
- MOV / MP4のApple QuickTime撮影日時（時差付き）を優先し、なければmvhd作成日時（UTC）を取得。保存日時の可能性があるため、動画は必ず確認が必要。
- 撮影日時が不明なら入力するまで書き出しをブロック。ファイル名・選択順・ファイル更新日時から撮影順を推測しない。
- 1枚目の写真は3秒、2枚目以降の写真は全体共通で1秒・1.5秒・2秒から選択（初期値1秒）、動画は冒頭最大4秒。4秒未満の動画は利用できる長さを使用。30fpsに合わせて端数フレームを切り下げ。
- 時系列を守って最大180秒に構成。多い場合は時刻範囲から間引き。品質・類似判定ではありません。足りない場合は長さを表示し、繰り返さず短いまま出力。
- 1920×1080 / 1280×720（初期値）/ 960×540から出力サイズを選択。16:9 / 30fps / H.264 VBR目標5 / 2.5 / 1.5Mbps、AAC目標128kbpsのMP4。AACの末尾パディングが完成尺を延ばさないようパケット長を調整。
- 1枚目の写真の最初の2秒に、日付と場所を左下へ表示。撮影日の元の現地日付とIPTC/XMPの地名を読み込み、GPSのみなら緯度・経度を使用。地名の外部検索は行いません。出力前にプレビューで確認・修正し、確認チェックが必要です。空欄の項目は表示しません。
- 無料の自動BGM：アカウント不要。CC0音源をインターネット経由で取得します（通信が必要）。動画の元音声を残し、写真の表示時間を変えてもBGMは途切れません。
- すべての写真に自動PAN・ZOOM。方向・拡大縮小・移動量を写真ごとに変え、規則的な動きの繰り返しを減らします。
- 人物・風景を問わず、写真全体にカメラ移動を適用します。写真の一部をAI生成・変形する機能ではありません。
- 写真は縦横比を保ったまま16:9画面を覆うサイズへ拡大し、黒帯をなくします。はみ出す上下・左右はトリミングされます。
- 動画はアスペクト比を維持して黒帯内に配置、冒頭・末尾の短いフェード、動画の元音声、写真区間の自動BGM、最後の音声フェード。BGMは自動で付きます。写真区間の音量を上げ、動画の元音声がある区間ではBGMを抑えます。
- 完成プレビュー、ダウンロード、対応端末のファイル共有。

180秒のサイズ目安は1080pで約115MB、720pで約59MB、540pで約37MBです。VBRなので実際の大きさは素材・ブラウザで変わります。

## 制約と未実装

- **iPhone実機検証は未実施**。モバイル表示を再現したChromiumで動作確認しています。Safariを模擬した検証ではありません。
- WebCodecsのH.264エンコーダーが必須。起動時に端末の対応を検査します。古いSafariや非対応ブラウザではボタンを無効にして代替を案内します。対応OSの断定ではなく実機の機能判定を使用しています。
- ネイティブAACエンコーダーがない場合だけ無料のAAC WASM補完を読み込みます。H.264エンコード・素材の映像／音声デコードには対応端末が必要です。
- HEICはOS・ブラウザがデコードできる場合に利用可能。非対応時はJPEGへの変換を案内します。MOVもコンテナ名だけでは保証できず、HEVCなどの内部コーデックに依存します。失敗した素材は除外し、残りで作成できます。
- 4K・HDRの色を完全に維持する処理は未実装。Canvas経由でSDRへ変換される可能性があります。フィルターによる色変更は行いませんが、HDRや広色域素材の元色再現は保証しません。
- バックグラウンド編集は非対応。画面ロックを可能なら抑制しますが、OSの停止・Safariのメモリ制限を回避できません。初回は少数の素材で試し、失敗時は素材を減らしてください。
- 原本は全てメモリへ読み込まずFileから必要範囲だけ読みます。画像は1枚ずつ、映像は縮小したフレーム、音声は1カットずつ処理します。ただし完成MP4はメモリに保持し、端末によっては長尺・巨大画像で終了する可能性があります。
- メタデータが削除・変更されている素材の撮影日時は復元できません。QuickTime moovのメタデータが16MBを超える場合や未対応構造では手動入力になります。
- 高精度な人物輪郭・奥行き推定による2.5D、良い素材の選択、手ブレ判定、会話検出、複数カット抽出、重複除去、AI音楽生成はPhase 2以降です。自動BGMはDURU-AIによるCC0録音済み楽曲を使用し、毎回ランダムに選曲します。楽曲提供元: https://github.com/uncle-sheepsky/duru-ai-cc0-bgm （CC0 1.0）。場所や出来事の意味理解は行いません。動画の音声トラックがある区間ではBGMを下げ、ミックス時のピークを抑えます。
- 写真アプリへの直接保存・バックグラウンド処理は将来のネイティブ版で実装します。

## 開発環境で起動

Node.js 24とnpmを使用します。

```sh
npm ci
npm run dev
```

開発サーバーが表示したURLをパソコンのブラウザで開きます。`index.html`のダブルクリックでは動作しません。iPhoneのWebCodecsはセキュアコンテキストが必要なので、iPhoneではHTTPSのGitHub Pagesを利用してください。

```sh
npm test
npm run build
npm run preview
```

ブラウザ自動テストはFFmpeg / ffprobeも必要です。テスト用の人工画像・音声付き動画はテスト中に一時ディレクトリへ生成します。利用者の旅行素材は使いません。

```sh
npx playwright install chromium
npm run test:e2e
# 環境にChromiumがある場合
CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e
```

## GitHubへの保存と無料公開（初心者向け）

この環境ではGitHubの新規作成APIがForbiddenとなるため、リポジトリの手動作成が必要です。コード・README・.gitignore・公開用ワークフローは用意済みです。

1. GitHubにログインし、右上の **＋ → New repository** を選びます。
2. Ownerを `hirocoppa`、Repository nameを `ai-travel-movie` にします。
3. 無料のGitHub Pagesで公開するため **Public** を選びます。公開されるのはアプリのコードで、ユーザーの旅行素材ではありません。
4. **Add a README file はオフ、Add .gitignore とChoose a licenseは未選択** のまま **Create repository** を押します。README・.gitignore・LICENSEは今回のコードに含まれているため、GitHub側で重ねて作らないでください。
5. このチャットで「リポジトリを作成しました」と知らせてください。作成済みコードをコミットしたmainブランチをpushします。自分で行う場合はこのプロジェクト内で `git push -u origin main` を実行します。
6. GitHubで **Settings → Pages → Build and deployment → Source → GitHub Actions** を選びます。
7. **Actions → Deploy Pages → Run workflow → main → Run workflow** を実行します（mainへのpushでも起動します）。
8. ワークフローが成功したら、Settings → Pagesに表示された公開URLをiPhoneで開きます。

公開URLの想定は `https://hirocoppa.github.io/ai-travel-movie/` です。実際の公開が完了するまでは利用できません。この開発中に公開済みであるとは主張していません。

## 構成

- `src/main.tsx`：画面、確認、保存操作
- `src/metadata.ts`：EXIF / QuickTime解析と素材の互換性確認
- `src/model.ts`：時系列編集計画（UIやエンコーダーと独立）
- `src/exporter.ts`：MP4作成（将来ネイティブ実装へ差し替える境界）
- `src/model.test.ts`, `src/metadata.test.ts`：撮影日時・編集計画のテスト
- `tests/movie.spec.ts`：ブラウザでの書き出し・保存・音声検証
- `.github/workflows/pages.yml`：ビルド・テスト・GitHub Pagesデプロイ
- `docs/architecture.md`：将来のiPhone／音楽生成設計
- `docs/music-research.md`：無料音楽モデルの調査と制約
- `public/licenses/`：依存ライブラリのライセンス・ソース案内

### 写真の自動PAN・ZOOM
写真ごとに方向・ズーム量・開始位置を変え、左右・上下・斜めへのPANとズームイン・ズームアウトを組み合わせます。設定や個別プレビューは不要です。Canvas 2Dで端末内描画し、写真はアップロードしません。
